WolfGuard Agent - Windows 10/11 x64

L'agent fonctionne en arriere-plan, sans fenetre ni icone a gerer.
Les postes, scans, alertes EDR, blocages et connexions se gerent sur le site.

1. Telecharger puis ouvrir WolfGuard-Agent-Windows.exe normalement.
2. Dans WolfGuard > Agents, generer un code temporaire.
3. Cliquer sur Associer ce poste. Autoriser l'ouverture du lien WolfGuard.
   Ou lancer Associer-agent.cmd et coller le code temporaire.
4. Choisir le poste dans Agents. L'agent demarre automatiquement avec la session.

Une association existante est conservee pour le meme utilisateur Windows.
Pour administrer les protections natives, apres cette association, relancer
une fois l'executable comme administrateur. Le composant est alors installe
dans ProgramData avec une tache de demarrage et des fichiers restreints.
Si le composant privilegie doit etre associe de nouveau apres revocation,
lancer Associer-agent.cmd comme administrateur avec un nouveau code temporaire.

Le code personnel WolfGuard ne doit jamais etre saisi dans l'agent.
Le jeton d'association est protege par Windows DPAPI.
Node.js est telecharge au premier lancement depuis nodejs.org et verifie
par SHA-256. L'executable n'est pas signe numeriquement.
Diagnostic utilisateur : %LOCALAPPDATA%\WolfGuardAgent\agent.log
Diagnostic du composant privilegie : %PROGRAMDATA%\WolfGuardAgent\<SID>\agent.log

Le nouvel agent remplace l'ancienne fenetre. Pour arreter l'agent :
WolfGuard-Agent.exe --stop (comme administrateur pour le composant privilegie).
La revocation depuis le site coupe son acces. Fermer le navigateur n'arrete
pas l'agent. Aucun port entrant n'est ouvert.

EDR : remontes Defender et pare-feu toutes les 30 secondes, alertes et actions
natives confirmees par poste. Les politiques maintiennent les protections
activees ; le mode observation ne les desactive pas. Defender passif ou un
antivirus tiers est indique sans inventer de protection active.
Les audits ponctuels restent dans Vulnerabilites, sans correctif automatique.
Les scans reseau, rapports, bureau et terminal restent disponibles sur le site.

Sources : https://github.com/cantinbruno/wolfguard/tree/main/agent

TERMINAL DISTANT
Dans Prise en main, choisir Terminal puis Se connecter.
PowerShell execute les commandes avec les droits de la session de l agent,
sans ouvrir de console. Le dossier courant est conserve entre commandes ;
les variables et les autres etats du shell ne sont pas conserves.
Les sorties et erreurs arrivent au fil de l execution. Interrompre arrete
la commande et son arbre de processus. Une seule commande a la fois,
60 secondes et 65 536 caracteres de sortie au maximum.
Les programmes interactifs ne sont pas pris en charge.
Deconnecter, quitter la rubrique ou arreter l agent
ferme le terminal et interrompt la commande. La session dure au plus 20 minutes.
Les commandes et leurs sorties sont chiffrees sur le relais et supprimees
de la session a sa fermeture. Aucun port entrant supplementaire n est ouvert.
Le terminal necessite cette nouvelle version de l agent.

PRISE EN MAIN DU BUREAU
Dans WolfGuard, ouvre Prise en main puis Demander la connexion.
Le poste utilise toujours l agent choisi dans Agents.
Sous Windows, un poste deja associe se connecte sans confirmation locale.
Sous Linux et macOS, les autorisations du bureau peuvent etre necessaires.
Un bouton local permet de terminer le partage ; Arreter l agent le termine aussi.
La session expire apres 20 minutes, a la fermeture de la rubrique ou si la liaison est perdue.
La premiere demande telecharge Koffi et jpeg-js depuis npm, avec versions
et empreintes SHA-512 imposees dans remote-dependencies.json. Aucun programme
d installation n est execute. Les licences sont incluses dans le cache local.
Windows : nouvel agent graphique, session utilisateur ouverte. Les fenetres
elevees, verrouillage et demandes UAC restent soumis aux restrictions Windows.
macOS : autoriser le processus de l agent ou Terminal/Node dans Accessibilite
et Enregistrement de l ecran. Relancer l agent apres les autorisations si necessaire.
Linux : session graphique, zenity ou kdialog (xmessage est un recours sous X11).
Wayland utilise le portail RemoteDesktop/ScreenCast et PipeWire. Installer
GStreamer : gstreamer1.0-tools, gstreamer1.0-pipewire et gstreamer1.0-plugins-good
sur Debian/Ubuntu. Les permissions du portail sont demandees a chaque session.
Le flux conserve la capture la plus recente pendant les echanges reseau et
vise jusqu a 15 images par seconde ; la cadence reelle depend du poste et du relais.
Le bureau est transmis sous forme d images pour l administration, sans audio
ni transfert de fichiers. Le flux passe en HTTPS par le relais WolfGuard ;
la derniere image et les actions en attente y sont chiffrees temporairement.
Le relais les dechiffre : ce n est pas un chiffrement de bout en bout.

Les produits et versions observes sont rapproches en ligne des avis et alertes CERT-FR par le serveur WolfGuard. Les liens CERT-FR et CVE apparaissent dans le rapport web et le PDF. Un port seul ne confirme pas un logiciel ni une vulnerabilite. Mettre a jour cet agent pour inclure les applications installees dans l audit.
