WolfGuard Agent — Linux et macOS

Le même agent exécute Scan passif, Scan actif, Cartographie et Vulnérabilités.

1. Extraire l’archive dans un dossier personnel.
2. Linux : ouvrir un terminal dans ce dossier et exécuter sh Start-Agent.sh
   macOS : ouvrir Start-Agent.command (ou exécuter sh Start-Agent.sh).
3. Dans WolfGuard, ouvrir Agents et générer un code temporaire.
4. Coller ce code dans le terminal. Garder le terminal ouvert pendant les scans.
5. Choisir ce poste dans Agents : toutes les sections l’utilisent.

Node.js 22+ est utilisé s’il est installé. Sinon, le lanceur prépare un moteur
officiel vérifié par SHA-256 dans le dossier personnel, sans installation système.
Architectures prévues : x64 et ARM64 ; Linux avec glibc, macOS Intel et Apple Silicon.
Sur une autre distribution, installer un Node.js 22+ compatible au préalable.

Ctrl+C arrête l’agent. Pour l’associer de nouveau : sh Start-Agent.sh --pair
Pour retirer son accès : Agents > Révoquer.
L’agent ne demande jamais le code d’accès WolfGuard.

L’association est conservée en dehors de l’archive :
Linux : ${XDG_CONFIG_HOME:-~/.config}/WolfGuardAgent/credential.json
macOS : ~/Library/Application Support/WolfGuardAgent/credential.json
Dossier 0700, fichier 0600, réservés au compte utilisateur (sans chiffrement OS).
Ne pas copier ce fichier pour distribuer ou partager l’agent.

Les collectes sont en lecture seule. Les sondes actives partent de cette machine.
Les contrôles d’audit s’adaptent au système : protections noyau, accès SSH,
pare-feu et cache de mises à jour sous Linux ; SIP, Gatekeeper, FileVault,
pare-feu et cache de mises à jour sous macOS.
Un contrôle inaccessible reste Non vérifié ; aucun correctif n’est appliqué.
Certains processus, pare-feu ou caches exigent des droits supplémentaires.

Scans reseau : le passif lit les voisins ARP/NDP, noms en cache, connexions et sockets connus pour la cible, sans sonde.
L actif analyse les services TCP de la seule cible IP ou FQDN indiquee
(4096 tests maximum). Les controles du poste restent dans Vulnerabilites.

Scans actif/passif : une seule cible IP ou FQDN obligatoire. Le passif ne résout pas les noms sur le réseau : fichier hosts ou cache DNS Windows uniquement. Si aucune association locale n’existe, le rapport explique l’absence de résultat. Les réseaux et plages restent réservés à la cartographie.

TERMINAL DISTANT
Dans Prise en main, choisir Terminal puis Se connecter.
Le shell /bin/sh execute les commandes avec les droits de la session de l agent,
sans ouvrir de fenetre. Le dossier courant est conserve entre commandes ;
les variables et les autres etats du shell ne sont pas conserves.
Les sorties et erreurs arrivent au fil de l execution. Interrompre arrete
la commande et son groupe de processus. Une seule commande a la fois,
60 secondes et 65 536 caracteres de sortie au maximum.
Les programmes interactifs ne sont pas pris en charge.
Deconnecter, quitter la rubrique ou arreter l agent ferme le terminal.
Les commandes et sorties sont chiffrees sur le relais et supprimees
a la fermeture. La session dure au plus 20 minutes.
Le terminal necessite cette nouvelle version de l agent.

PRISE EN MAIN DU BUREAU
Dans WolfGuard, ouvre Prise en main puis Demander la connexion.
Le poste utilise toujours l agent choisi dans Agents.
Une demande locale doit etre acceptee avant toute capture ou action.
Un bouton local permet de terminer le partage ; Arreter l agent le termine aussi.
La session expire apres 20 minutes, a la fermeture de la rubrique ou si la liaison est perdue.
La premiere demande telecharge Koffi et jpeg-js depuis npm, avec versions
et empreintes SHA-512 imposees dans remote-dependencies.json. Aucun programme
d installation n est execute. Les licences sont incluses dans le cache local.
Windows : nouvel agent graphique, session utilisateur ouverte. Les fenetres
elevees, verrouillage et demandes UAC restent soumis aux restrictions Windows.
macOS : autoriser le processus de l agent ou Terminal/Node dans Accessibilite
et Enregistrement de l ecran. Relancer l agent apres les autorisations si necessaire.
Linux : session graphique, zenity ou kdialog (xmessage est un recours sous X11).
Wayland utilise le portail RemoteDesktop/ScreenCast et PipeWire. Installer
GStreamer : gstreamer1.0-tools, gstreamer1.0-pipewire et gstreamer1.0-plugins-good
sur Debian/Ubuntu. Les permissions du portail sont demandees a chaque session.
Le bureau est transmis sous forme d images pour l administration, sans audio
ni transfert de fichiers. Le flux passe en HTTPS par le relais WolfGuard ;
la derniere image et les actions en attente y sont chiffrees temporairement.
Le relais les dechiffre : ce n est pas un chiffrement de bout en bout.

Le serveur WolfGuard rapproche les produits et versions observes des avis et alertes CERT-FR. Sous Linux, un inventaire cible de paquets est lu sans installation ni recherche de mises a jour reseau. Les correctifs retroportes par la distribution doivent etre verifies. Les liens CERT-FR et CVE sont conserves dans le rapport web et le PDF.
